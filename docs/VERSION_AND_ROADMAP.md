# FabMatrix 版本与路线地图

更新时间：2026-09-14

本文是前端文档的版本解释入口。它解决三个容易混淆的概念：产品发布版本、API 路径版本、Kiro 开发阶段编号。

## 1. 当前发布基线

| 项目 | 当前结论 |
| --- | --- |
| 产品名称 | 嘉东三维联动3D打印机实时控制系统 / FabMatrix |
| 产品版本 | `1.0.0` 准正式版 |
| 候选标识 | `v1.0.0-rc.1` |
| 发布形态 | Windows Local Edition：一个本地服务端 + 多个 Electron 客户端 |
| 默认服务端口 | `28081`；HTTP 与 WebSocket 使用同一后端端口 |
| 数据形态 | SQLite/本地文件存储；不把 MySQL、Redis、RustFS 作为本版本安装前提 |
| 当前发布门禁 | `.kiro/specs/farm-v1-release-readiness/` 和 `npm run release:gate` |

1.0.0 准正式版的目标是完成可安装、可启动、可初始化、可登录、可联机和核心业务可回归的本地版。真实 Windows 安装/升级/卸载、真实打印机和长时间网络稳定性仍需在实际环境完成验收后，才能标记为正式发布。

## 2. 版本术语映射

| 术语 | 实际含义 | 处理方式 |
| --- | --- | --- |
| `1.0.0` | 当前对外产品版本 | 所有前端、Electron、服务端和安装器对外统一使用 |
| `/api/v1` | HTTP API 的兼容路径 | 保持不变，不改成 `/api/1.0.0` |
| v1 | 最初的业务/协议基础能力和历史验收阶段 | 作为历史基础保留 |
| v2 | 手动优先、Local Edition、任务可读性和文件管理等功能阶段 | 作为功能实现来源保留；是否进入 1.0.0 由 R100 门禁决定 |
| v3 | 后台自动派单及更高风险批量派发路线 | 1.0.0 隐藏或不开放，后续单独发布 |

因此，Kiro 目录名和任务编号中的 v1/v2/v3 不应直接替换成产品版本号，也不能据此判断某个接口是否属于当前发布范围。

## 3. Kiro 规格归属

| 规格 | 状态 | 归属 |
| --- | --- | --- |
| `farm-v1-release-readiness` | 当前发布门禁 | 1.0.0 准正式版；R100 任务以真实验证结果为准 |
| `farm-ui-v2` | 历史功能基线 | 手动上传、文件库、任务中心、权限和看板等功能来源；不等于“发布 v2” |
| `farm-v3-batch-dispatch` | 后续规划 | 后台自动派单、批量执行和恢复模型；不进入 1.0.0 发布门禁 |
| `farm-dashboard-dynamic-layout` | 功能规格/验收记录 | 看板动态行列和过道编辑，按 R100 范围决定是否随版本交付 |
| `farm-task-center-readability` | 功能规格/验收记录 | 任务可读名称、快照和历史显示 |
| `printer-*` | 协议、监控和 WebSocket 规格 | 以真实设备联调状态为准 |
| `farm-ui-remediation`、`farm-ui-selective-integration` | 历史整改/合并记录 | 只作为变更依据和回归证据 |

## 4. 文档权威顺序

出现冲突时按以下顺序判断：

1. 当前代码、实际配置和自动化验证结果；
2. `farm-v1-release-readiness` 的发布范围与验收记录；
3. `API_HANDOFF.md` 的接口契约；
4. 具体功能 Kiro 的 requirements/design/tasks；
5. 根目录 TODO 和历史说明。

根目录 TODO 允许保留历史任务，但不得用来覆盖 R100 的发布范围。

## 5. 当前未纳入 1.0.0 的能力

- 后台无人确认的自动派单。
- 依赖 MySQL、Redis、RustFS 的 Server Edition 安装交付。
- 未完成真实设备验证的协议或控制能力。
- 未通过安装器、升级、卸载和数据保留验收的发布结论。

## 6. 新任务维护规则

- 新任务先注明产品版本和 Kiro 规格归属，再写实现任务。
- 产品版本统一写 `1.0.0`；历史阶段可写“v2 功能基线”，不要写成“产品 v2 发布”。
- 涉及接口时保留 `/api/v1`，并说明这是 API 路径而非产品版本。
- 完成任务后同步对应 `tasks.md`、接口契约、验证记录和本索引；不要批量改名历史目录。
