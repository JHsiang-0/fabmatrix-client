# Client 完整设备模型

## 入口与数据来源

打印机管理和看板共用 `DeviceDetailDrawer`。设备概览中的“运行状态”通过本地 HTTP 接口 `GET /api/v1/printers/{id}/model` 读取 Server 持久化的统一设备模型，当前支持 modelVersion 2。列表、看板和 WebSocket 继续使用轻量状态摘要。

Server 负责 Klipper、RRF 采集和字段映射。Client 根据业务场景选择显示数据。

列表、详情聚合与 WebSocket 现在优先使用 Server 从统一模型生成的 `stateSummary`，校验版本和本地设备 ID，并根据服务端时间加接收后的本地间隔判断 30 秒新鲜度。无有效模型、离线、停止监控或过期时，清空当前温度、进度和文件摘要，不回退到旧字段。共享读取时钟每秒更新，数据中断也会过期；本地任务绑定和安全确认保持独立。旧服务端未返回 `stateSummary` 时才使用原兼容读取路径。

2026-11-05 验证：456 项 Node 测试、39 项浏览器检查（4 项未启用功能跳过）、2 项 Electron dist 检查及 `npm run release:gate` 通过，包含模拟列表摘要与真实 Pinia/Axios/WebSocket 合并及过期回归。未安装桌面客户端、未操作生产打印机。本轮测试并发限制为 4 个文件，避免本机多仓库联调时默认并发耗尽内存。

- 设备概览突出状态、进度和多路温度卡片。设备正在执行任务时展示已打印时间、预计剩余、层数和耗材。未提供的可选指标省略，温度等关键指标缺失时明确显示不可用。
- “更多运行信息”默认折叠，按设备实际报告展示加热功率、风扇、坐标、归零和传感器。没有有效字段的分组省略，测量提示保留质量、来源与采样时间。
- “设备信息”页集中展示地址、协议、耗材、喷嘴和监控配置。“历史统计”按原有入口提供。
- 最近执行结果作为独立历史摘要显示。内部 UUID、版本号、能力枚举、文件摘要和原始字段列表由模型继续承载。

详情顶部的状态、通信和进度优先使用完整模型。内部任务编号、安全确认和控制动作仍由现有本地业务接口处理。

## 新鲜度与生命周期

- 概览可见时每次请求完成后间隔 5 秒刷新，失败后间隔 30 秒重试，也可手动刷新。
- 关闭抽屉、切换设备、切换历史页、隐藏窗口或退出账号时取消请求并清空上下文。忽略取消信号的旧响应也不会覆盖新设备或新会话。
- 采用 Server 时间校准设备数据年龄，每秒重新判断。监控关闭、非在线、采样超过 30 秒及异常未来时间均不能作为当前状态。
- 每个测量还需质量为 GOOD 且时间有效。0 和 false 保留，缺失值不补成 0。计数超过 JavaScript 安全整数范围时显示无效数据。
- 离线时温度显示占位，当前打印统计收起，上次执行结果独立显示。刷新失败后清除前次模型并展示重试入口。
- 未采样展示空状态，旧 Server 没有此接口时展示请求错误。需同时更新 Server 和 Client。

## 维护与验证

API 封装位于 `src/api/printer.js`，显示适配位于 `src/utils/printerModel.js`，轮询隔离位于 `src/utils/printerModelLoader.js`，界面位于 `src/components/device/PrinterModelPanel.vue`。

`npm run test:printer-model` 覆盖模型契约、质量与新鲜度、历史结果、摘要转换、请求竞态及 Mock 权限。浏览器专项场景通过打印机管理真实打开详情，验证多通道、离线、错误、桌面和紧凑窗口展示。提交前执行 `npm run lint:check`、`npm test`、`npm run build`，发布执行 `npm run release:gate`。
