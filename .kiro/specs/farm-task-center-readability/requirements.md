# FabMatrix 任务中心可读性与可靠性改造需求

版本：v1.0
任务标识：TC-001 ～ TC-008
任务类型：前后端联合整改
状态：待实施
涉及项目：`fabmatrix-client`、`fabmatrix-server`

## 1. 背景

当前任务队列、活动任务、打印历史和任务详情主要展示 `jobId`、`fileId`、`printerId`、`userId`、`operatorId`。真实后端 `PrintJobVO` 未返回文件名、打印机名称、机器编号或用户名，导致用户无法快速识别任务对象。

同时存在以下可靠性问题：

- 活动任务按每种状态只读取第一页 100 条，超过上限会静默遗漏。
- 打印历史默认包含排队、上传、打印、暂停和核对中等非终态任务，页面名称与数据语义不一致。
- 历史时间筛选实际使用 `createdAt`，不能按完成时间查询。
- 未知任务的 WebSocket 消息可能在前端构造缺少文件和打印机信息的不完整任务。
- 重试复用原任务记录并清空部分执行信息，无法保留完整失败历史。
- 前端、Mock、后端对部分状态、操作矩阵和响应数据的描述不一致。

## 2. 用户目标

生产人员应能通过文件名称、机器编号、打印机名称和操作人员快速识别任务；技术 ID 仅作为辅助排障信息。任务队列、活动任务和打印历史必须对应清晰且互不混淆的数据集合。

## 3. 功能需求

### R-TC-001 可读任务摘要

任务队列、活动任务、历史分页和任务详情应返回并展示：

- `fileName`
- `printerName`
- `machineNumber`
- `creatorUsername`
- `operatorUsername`

要求：

- 文件名和打印机名称作为主信息，ID 作为次级信息或详情中的技术字段。
- 未分配打印机显示“未分配”，不能显示空白、`null` 或 `undefined`。
- 关联资源已删除或无权限读取时，仍保留任务记录并使用名称快照或 ID 回退。
- 禁止前端逐任务调用文件、打印机或用户详情接口补名称。

### R-TC-002 队列语义

- 待派发队列只包含规范化后的 `QUEUED`。
- 排序固定为 `priority DESC, createdAt ASC, id ASC`。
- OPERATOR 只查询本人任务，权限条件必须在数据库查询阶段生效。
- GET 查询不得迁移状态或写数据库；遗留 `PENDING/MANUAL/CANCELED` 通过独立迁移处理。

### R-TC-003 活动任务完整分页

活动任务集合固定为：

- `ASSIGNED`
- `UPLOADING`
- `READY`
- `PRINTING`
- `PAUSED`
- `RECONCILING`

要求服务端支持多状态分页或等价的专用活动任务分页，前端不得按状态各取前 100 条后本地拼接。

### R-TC-004 打印历史语义

打印历史默认且只能展示终态：

- `COMPLETED`
- `FAILED`
- `CANCELLED`

要求：

- 支持按终态、打印机、文件名、创建人和完成时间筛选。
- 时间筛选必须明确区分 `createdAt` 与 `completedAt`，历史页默认使用完成时间。
- 分页排序固定为 `completedAt DESC, id DESC`，避免同一时间数据跨页漂移。

### R-TC-005 历史名称与执行快照

历史记录应优先显示任务发生时的快照：

- `fileNameSnapshot`
- `printerNameSnapshot`
- `machineNumberSnapshot`
- `creatorUsernameSnapshot`
- `operatorUsernameSnapshot`

资源改名或删除后，不得改变既有历史的主显示内容。

### R-TC-006 重试与尝试记录

- 重试不得清除原失败记录的打印机、操作员、开始时间、完成时间和错误原因。
- 采用新的任务记录并保存 `retryOfJobId`，或增加 `farm_print_job_attempt` 执行尝试表。
- 每次尝试保留状态、设备、操作员、开始/结束时间、进度和失败原因。

### R-TC-007 实时状态收敛

- WebSocket 增量只更新消息明确提供的字段。
- 未知 `jobId` 不得直接插入不完整活动行，应触发受控详情加载或列表刷新。
- 状态转换后任务应在待派发、活动和历史三个集合之间正确移动。
- 兼容正式消息中的 `jobId` 位置，并通过 sequence/eventId 防止旧消息覆盖新状态。

### R-TC-008 权限、状态机与错误

- ADMIN 可查看全部任务；OPERATOR 只查看本人可访问任务。
- 详情、重试、重排、取消、核对和控制操作以后端状态机为最终边界。
- `RECONCILING` 只能通过人工核对接口完成、失败、取消或重新排队，不能调用设备控制代替核对。
- 统一处理 400/401/403/404/409/422/503，失败后保留上下文并重新同步服务端状态。
- 所有写操作防重复点击并展示 loading。

## 4. 非功能要求

- Long ID 继续按 JSON 字符串传输，前端不得转为 Number。
- 关联查询禁止 N+1；列表页应使用单次 JOIN 或固定次数批量查询。
- 新增字段采用向后兼容的增量契约，旧 ID 字段保留。
- 任务表格在 Electron 800×560、1024×640、1200×760 下可滚动，首尾操作可达。
- 文件名、打印机名、机器编号和用户名过长时省略，Tooltip 展示完整值。

## 5. 验收标准

- 队列、活动、历史和详情均以名称为主、ID 为辅，不再出现仅靠 ID 判断任务的主视图。
- 单一活动状态超过 100 条时仍能完整分页访问。
- 历史页不出现任何非终态任务，并按完成时间查询和排序。
- 打印机或文件改名、删除后，旧历史仍显示任务发生时的名称快照。
- 重试后原失败尝试仍可审计。
- WebSocket 状态转换不会产生缺少文件名或打印机信息的空壳任务。
- ADMIN/OPERATOR 数据范围和写操作权限符合后端契约。
- Mock、OpenAPI、API 交接文档、前端类型说明和真实接口保持一致。
