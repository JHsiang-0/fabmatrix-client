# Ardot + TDesign 前端原型需求

版本：1.0.0 准正式版
规格：`farm-ardot-tdesign-prototype`
状态：规划中
依据：当前 Vue 路由、现有页面组件、`AGENTS.md`、`docs/VERSION_AND_ROADMAP.md`
设计工具：Ardot
组件库：Ardot 中的 `TDesign for web`

## 目标

在 Ardot 中建立一套可评审、可交付、可继续编码的 FabMatrix 前端高保真原型。原型应还原现有桌面应用的信息架构和业务流程，并使用 Ardot 组件库中的 TDesign for web 真实组件实例作为后续编码依据。

本任务解决的问题不是“把几个组件拖到画布上”，而是将应用壳、页面内容、抽屉/弹窗、状态和响应式约束组成完整的业务页面，避免出现组件散落、层级不清和与现有前端无法对应的原型。

## 需求

### REQ-01 原型文件和页面组织

1. Ardot 文件中必须有明确命名的原型页面，不得只使用默认的 `Page 1`、`Page 2`。
2. 原有手动画稿保留为备份，新原型使用独立页面，评审通过前不得覆盖或删除备份。
3. 页面按“基础应用壳、打印机管理、文件库、任务中心、全屏看板、状态与弹层”组织，页面名称能够与 Vue 路由或视图对应。
4. 画布采用适合桌面端评审的固定基准尺寸，默认基准为 1440×900；同时提供 800×560 窄窗口检查结果。

### REQ-02 TDesign 组件真实性

1. 按钮、输入框、搜索框、标签、卡片、选项卡、树、上传、抽屉、对话框、开关、进度、分页、表格等控件，优先使用 `TDesign for web` 真实组件实例。
2. 每个真实组件在 Ardot 中应能通过选中后的组件属性面板确认来源为 `TDesign for web`。
3. 组件的尺寸、主题、状态、边框、圆角、颜色和交互反馈优先采用组件库默认属性及设计变量；不得用自定义视觉体系替代 TDesign。
4. 组件库没有完整业务表格实例时，使用表头、列、行和选择框等 TDesign 表格子组件组合，不得把 16×16 的表格图标误认为完整表格。
5. 所有组件命名和页面节点命名应便于后续映射到 Vue 组件，不使用无意义的随机名称。

### REQ-03 应用壳和导航

1. 标题统一为“嘉东三维联动3D打印机实时控制系统”，与当前应用和 Electron 标题栏一致。
2. 原型包含桌面标题栏、品牌区域、侧边导航、用户区域和主内容区。
3. 导航能表达工作台、打印机、文件、任务、管理中心和个人中心的层级关系。
4. 页面内容区有明确的页面标题、工具栏、筛选区、数据区和状态反馈区，不能只呈现孤立控件。

### REQ-04 核心业务页面

原型至少包含以下完整页面，并与当前路由对应：

| 页面 | 对应路由/视图 | 必须体现的内容 |
| --- | --- | --- |
| 打印机管理 | `/printers`、`PrinterManage.vue` | 状态筛选、搜索、刷新、扫描、添加打印机、表格、固定选择列和操作列、状态标签、监控状态 |
| 文件库 | `/files`、`FileLibrary.vue` | 文件夹树、搜索、上传、列表/卡片切换、文件信息、分页、空状态、文件详情抽屉 |
| 任务队列 | `/tasks/queue`、`JobQueue.vue` | 可读文件名、打印机名、创建人、任务状态、进度、时间、详情抽屉和安全操作入口 |
| 打印历史 | `/tasks/history`、`JobHistory.vue` | 文件和设备可读名称、结果状态、失败/核对说明、筛选和分页 |
| 全屏看板 | `/dashboard/fullscreen`、`FullscreenDashboard.vue` | 顶部标题、统计卡片、动态行列、过道、设备绑定、绑定弹窗和布局设置 |

### REQ-05 弹窗、抽屉和异常状态

每个涉及业务操作的页面至少提供以下状态：

1. Loading：首次加载、刷新、扫描、上传、批量导入和提交时的反馈。
2. Empty：无数据、未选择目录、尚未扫描和无关联任务。
3. Error：请求失败、服务不可用、设备离线、导入失败和操作冲突。
4. Disabled：无权限、设备不可用、未选择数据和功能开关关闭。
5. Hover/Active/Selected：表格行、卡片、树节点、看板位置和设备列表项。
6. 确认弹窗：删除、取消、急停、安全确认等不可逆或高风险操作。
7. 人工核对：任务进入 `RECONCILING` 或无法确认终态时，必须有明确的核对入口、说明和结果操作。

### REQ-06 设备扫描和详情交互

1. 局域网扫描使用抽屉形态，网段输入拆分为前三段固定/可配置输入和最后一段范围配置，扫描按钮独立位于右侧。
2. 扫描结果采用紧凑卡片或两行信息结构，展示设备名称、IP、协议、MAC 和已知/新增状态，禁止产生横向滚动条。
3. 打印机详情抽屉包含当前状态、通信状态、温度、当前任务、状态历史和 RRF/DWC 控制入口等信息层级。
4. 同一状态的连续实时更新要合并或降噪，避免状态历史被相同记录撑满。

### REQ-07 响应式和桌面窗口约束

1. 在 1440×900 下页面布局完整，内容不被遮挡，卡片、表格和抽屉边界清晰。
2. 在 800×560 下，打印机表格和详情内容可在区域内滚动，首列选择框和末列操作列保持可见或有明确固定策略。
3. 文件夹树在新增一级层级后仍能显示完整标题、搜索框和新增按钮，不因外框加宽而留下无意义空白。
4. 长文件名、长设备名、连续状态文本和多条扫描结果必须截断、换行或折叠，不得溢出或撑爆布局。

### REQ-08 原型交付和编码交接

1. 每个页面提供页面说明、关键组件清单、状态说明和交互注释。
2. 原型中的组件能够映射到现有 `src/components`、`src/views` 和 `src/utils`，无法映射的部分必须标注为新增组件或待确认。
3. 交付时提供 Ardot 文件链接、页面清单、组件映射表、桌面尺寸检查截图和待确认项。
4. 原型评审通过后才允许进入 Vue 编码阶段；本任务本身不修改生产代码、API 契约或后端逻辑。

## 非目标

- 不在本任务中修改 Vue 页面、Pinia Store、API 模块或后端代码。
- 不新增自定义 CSS 视觉体系，不以手动画框替代 TDesign 组件实例。
- 不改变 `/api/v1` 接口路径、权限规则和当前 1.0.0 发布范围。
- 不删除现有 Ardot 手动画稿或仓库中的历史 Kiro 规格。
- 不把 V3 批量派发能力重新纳入 1.0.0 发布门禁。

## 验收总则

原型必须能让开发人员仅依据页面、组件属性和交互注释，明确知道“页面长什么样、使用什么组件、有哪些状态、后续对应哪个 Vue 页面”。只完成组件拖拽、页面缩放过小或无法识别业务结构，均不视为完成。
