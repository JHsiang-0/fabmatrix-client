# SYNC-002 动态看板布局需求

## 1. 背景与目标

当前全屏看板仅支持固定 `4 × 12` 物理网格，并在第 7 个物理列后插入一条固定纵向过道。前端尺寸、矩阵和 CSS Grid 均依赖常量，后端只保存打印机的 `gridRow/gridCol`，没有布局配置、槽位唯一性、布局版本或可靠的批量事务。

本 Spec 的目标是建立单农场共享的动态看板布局：管理员可编辑物理行数、物理列数、横向/纵向过道和设备位置；操作员只读；布局、坐标和多客户端状态以服务端为唯一事实来源。

本 Spec 不引入车间实体、车间切换或用户私有布局，也不恢复 `30adedc` 中虚假的多车间数据。

## 2. 实施前基线（历史）

以下内容只记录 SYNC-002 实施前的问题，不代表当前实现；当前行为以本文后续验收标准、设计文档和 API handoff 为准。

- `src/utils/constants.js` 固定 `ROWS: 4`、`COLS: 12`、`AISLE_COL: 8`。
- `GridMap.vue` 固定渲染 4 行、13 个视觉列，只识别一条纵向过道。
- `deviceStore.fetchDeviceData()` 只读取打印机分页第一页、最多 100 台；重复坐标会在前端 Map 中覆盖并隐藏设备。
- `PUT /api/v1/printers/positions` 对越界、不存在设备和 SQL 异常采用跳过策略，可能返回部分成功。
- 当前数据库没有布局表、坐标成对约束和槽位唯一约束。
- `30adedc` 中的动态行列、横纵过道、坐标映射和视口计算可作为实现参考，但其中 localStorage 持久化不能作为正式数据源。

## 3. 范围决策

### R1：布局作用域与默认值

- 首版只提供一个农场级共享布局。
- 默认布局兼容现状：4 行、12 个物理列，在物理第 7 列后插入一条名为“过道”的纵向过道。
- 服务端返回布局版本和限制能力；行数固定为 `1–30`、列数固定为 `1–60`、总物理槽位不超过 `1800`。
- 前端不得以 localStorage 覆盖服务端布局；localStorage 只可保存非业务偏好，例如缩放模式。

### R2：过道模型

- 支持零条或多条横向、纵向过道，以及两类过道的交叉区域。
- 每条过道包含稳定 ID、方向、插入位置、名称和尺寸。
- `afterIndex=0` 表示位于第一行/列之前；其他值表示位于对应物理行/列之后。
- 同一方向、同一插入位置最多一条过道；总数最多 20 条；名称最多 12 个字符；尺寸范围 `48–240` CSS px。
- 过道只改变视觉轨道，不占用物理坐标，也不改变已保存设备的 `gridRow/gridCol`。

### R3：读取与初始化

- ADMIN 和 OPERATOR 均可读取布局。
- 页面必须先取得 REST 布局和设备快照，再建立矩阵并应用 WebSocket 增量状态。
- 看板必须读取全部已分配设备，不能停留在打印机分页前 100 条。
- 无效、半空、重复或越界坐标必须进入明确异常清单，不能被静默过滤或覆盖。

### R4：编辑权限与交互

- 只有 ADMIN 可以进入布局编辑、调整行列、管理过道、绑定、移动、交换和下架设备。
- OPERATOR 可以查看动态布局和实时状态，但不显示或禁用所有布局写操作。
- 编辑过程使用前端草稿；取消时恢复最近一次服务端快照，保存成功后才替换权威布局。
- 行列和过道编辑优先使用 TDesign Dialog、Form、InputNumber、Alert、Button、Popup/Tooltip 等官方组件。
- 所有保存按钮需要 loading 和防重复点击；失败后保留可恢复的草稿并提供重新载入服务端布局的入口。

### R5：布局缩容

- 缩小行数或列数前，前后端都要计算越界设备。
- 默认策略为 `REJECT`：存在越界设备时拒绝保存，返回设备 ID、名称和原坐标，任何数据不得改变。
- 可选 `UNALLOCATE` 必须由管理员二次确认；确认后在同一事务中把所有越界设备的行、列同时置空。
- 不允许静默裁剪、自动挤压、覆盖其他设备或只在前端隐藏越界设备。

### R6：坐标完整性与原子性

- `gridRow/gridCol` 必须同时为空或同时非空；非空时均为正整数且位于当前布局内。
- 同一物理槽位最多绑定一台打印机。
- 一次布局保存中的行列、过道和位置变化必须整体校验、整体提交、整体回滚。
- 交换设备时允许事务内临时清空坐标，但提交后的数据库不得存在重复槽位。
- 不存在打印机、重复 printerId、重复目标槽位、被未参与本次编辑的设备占位或超过批量限制时，整次保存失败。
- 不再在绑定槽位时自动把槽位标签写入 `machineNumber`；槽位标签由布局和坐标计算，`machineNumber` 保持设备资产字段语义。

### R7：并发与多客户端同步

- 布局使用单调递增 `version` 做乐观锁；保存必须携带 `expectedVersion`。
- 两个管理员基于同一版本保存时，只允许第一个成功，后一个返回 409 并重新加载权威快照。
- 事务提交后按现有 WebSocket `version=1` 协议发布新增的 `LAYOUT_UPDATED` 事件；事件只通知布局版本变化，不覆盖设备业务状态或通信状态。
- WebSocket 断线期间保留最后布局；恢复后通过 REST/快照版本收敛，不能依赖遗漏的单条事件。

### R8：错误与权限语义

- 400：格式、范围、半空坐标、重复 ID/槽位或批量数量错误。
- 401：未认证。
- 403：OPERATOR 或其他非管理员尝试写入。
- 404：请求中包含不存在的打印机。
- 409：布局版本过期或槽位并发冲突。
- 422：缩容产生越界设备且策略为 `REJECT`。
- 5xx：数据库或服务异常；不得返回伪成功或部分成功。
- 前端统一展示后端消息，并在 409/422 场景展示可操作的冲突/越界详情。

### R9：数据库与发行版本

- Server Edition MySQL 和 Local Edition SQLite 必须同时支持。
- 新安装脚本和既有数据库增量迁移都要更新；已有 Docker 数据卷必须提供显式迁移说明。
- 迁移前审计半空坐标、重复槽位和越界记录；不得在迁移脚本中无提示删除或覆盖真实设备位置。
- 新增布局表，保留 `farm_printer.grid_row/grid_col`；动态上界由服务层根据布局校验。

### R10：非回归

- 保留当前打印机业务状态、通信状态和 WebSocket 增量合并规则。
- 保留看板详情、暂停、恢复、取消、急停、绑定、交换、移动和下架能力。
- 普通工作台不因全屏动态网格改造而改变统计和任务行为。
- 800×560 Electron 窗口和常用桌面分辨率不得产生页面级溢出；大网格应使用看板内部双向滚动，不能缩小到不可读。

## 4. 总体验收标准

- ADMIN 可创建并保存动态行列、横纵过道和设备布局；OPERATOR 只能查看。
- 刷新页面、重新登录或换客户端后布局一致，不依赖浏览器 localStorage。
- 1×1、默认 4×12、30×60、多过道和过道交叉均可正确渲染和映射坐标。
- 缩容、交换、冲突和故障注入均不会产生部分提交、重复槽位或静默丢设备。
- 两名管理员并发保存只有一个成功，失败端可重新载入最新布局。
- 看板可加载超过 100 台打印机，异常坐标有明确提示。
- MySQL/SQLite 的新库和已有库迁移均通过。
- 前后端测试、lint、build、浏览器 E2E 和 Electron E2E 全部通过。
