# FabMatrix V3 批量派发需求

## 目标

V3 重新提供可用于真实设备的批量派发能力。在满足事务一致性、设备状态、失败恢复和幂等验收前，V2 不向用户暴露入口，也不允许通过地址直接访问。

## 核心需求

- 批次计划认领使用短事务，每个派发项独立持久化；真实设备调用不得与整批数据库事务绑定。
- `UPLOAD_ONLY` 成功后稳定进入 `READY`，设备空闲不能触发异常核对。
- 会绑定打印机的派发动作中，一台打印机同一批次最多承接一个可执行项；容量不足必须在预览阶段明确展示。
- 预览和确认均校验通信在线、状态新鲜度、占用状态和兼容性。
- 资源版本不得使用会被监控心跳更新的通用 `updatedAt`。
- `RETRYABLE`、`RECOVERY_REQUIRED`、`EXECUTING` 和部分失败具有明确、可恢复的状态转换。
- 重复确认必须幂等回放；终态计划不受预览 TTL 影响。
- 冲突项不可确认；部分确认必须明确将未选项标记为 `SKIPPED`，或要求确认全部可执行项。
- 前端支持超过 100 条资源的分页或搜索选择、409 失效引导、选中资源失效清理和唯一错误反馈。

## V2 安全策略

- 侧边导航隐藏批量派发入口。
- `/batch-dispatch` 直接访问返回不可用页面。
- 保留页面、API、Mock、工具与测试资产，避免删除后丢失既有设计和契约。

## 权限与资源可见性冻结

- 只有已认证的 `ADMIN` 或 `OPERATOR` 可以创建批量预览；匿名用户和未知角色不得通过预览接口探测资源。
- 预览、确认和恢复都必须按当前会话重新校验文件和打印机权限，不能信任客户端传入的名称、角色或资源列表。
- 计划创建者可以确认、恢复和回放自己的计划；`ADMIN` 可以确认、恢复和回放任意计划。`OPERATOR` 不得确认、恢复或回放其他用户创建的计划，统一返回 403。
- 不可见的私有文件（包括不存在、已删除或无权访问的文件）统一返回 404，不泄露资源是否存在；同一规则适用于计划中的私有资源。
- 预览失败项必须保留 `FILE_NOT_FOUND` 等原因码但不回显私有资源元数据；不可执行项不得进入确认执行集合。

## 计划、明细与动作状态冻结

计划级状态转换：

```text
PREVIEWED -> EXECUTING -> COMPLETED
                     \-> PARTIAL_FAILED
                     \-> RECOVERY_REQUIRED
```

- `PREVIEWED` 只表示无副作用校验已完成；确认时短事务认领计划并进入 `EXECUTING`，设备调用不得包在整批数据库事务中。
- 所有选中明细成功后计划为 `COMPLETED`；成功与失败混合时为 `PARTIAL_FAILED`；设备副作用未知、进程中断或租约超时必须进入 `RECOVERY_REQUIRED`，不得伪报成功。
- 未选中的可执行明细必须明确标记 `SKIPPED`，冲突或不可见明细不可确认。`RECOVERY_REQUIRED` 只能经过恢复检查、重试或人工核对退出，不能直接跳到成功态。

明细级状态转换：

```text
PENDING -> ASSIGNED | QUEUED | UPLOADING
ASSIGNED/QUEUED/UPLOADING -> READY | SUCCEEDED
任一执行态 -> RETRYABLE | FAILED | RECOVERY_REQUIRED
PENDING -> SKIPPED
```

动作成功态冻结如下：

| action | 成功明细状态 | 语义 |
| --- | --- | --- |
| `UPLOAD_ONLY` | `READY` | 上传完成但不启动打印，不因设备空闲被误判为异常 |
| `QUEUE` | `QUEUED`；已绑定打印机时可为 `ASSIGNED` | 任务已持久化并等待队列/设备处理，不代表正在打印 |
| `START_AFTER_CONFIRM` | `ASSIGNED` 或 `QUEUED` | 已创建等待现场安全确认的任务；确认接口不得将其伪报为 `PRINTING` |

- `RETRYABLE` 必须携带可重试原因和尝试次数；不可重试错误进入 `FAILED`；无法确定设备副作用时进入 `RECOVERY_REQUIRED`。
- 确认执行使用 `EXECUTING` 租约（持有者、到期时间和尝试号）；服务启动恢复扫描到期租约，先核对数据库、任务和设备，再恢复、重试或转入 `RECOVERY_REQUIRED`。
- `RECOVERY_REQUIRED` 的退出必须产生可审计结果：核对为已完成则落入相应成功态，确认未执行则允许安全重试，无法判定则保持该状态并阻止重复副作用。

## 幂等规则冻结

- 预览返回计划版本、确认令牌和资源版本；确认必须校验计划 ID、版本、令牌、资源新鲜度和当前权限。
- 同一计划、明细集合和确认令牌的重复确认必须回放第一次结果，不得新增任务、重复占用打印机或重复调用设备。
- 终态计划的幂等回放不受预览 TTL 影响；非终态计划过期或版本冲突返回 409，并要求重新预览。
- 恢复和回放同样受计划创建者/`ADMIN` 权限约束，并以明细幂等键隔离并发确认；同一打印机在同一批次最多承接一个可执行明细。
