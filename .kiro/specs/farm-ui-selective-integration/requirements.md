# SYNC-001 远程界面改动选择性集成需求

## 1. 背景与目标

当前功能基线为本地 `feat/ui-003-electron` 的 `2896a55d7d0623d2ff798bf863ef0ebb35c99255`。
同事远程分支 `origin/feat/ui-003-electron` 当前为 `30adedc`，双方共同祖先为 `27bcc42`，本地与远程已经分叉。

本 Spec 的目标是：以本地功能基线为准，选择性吸收远程分支中的 TDesign 页面布局和视觉改动，保留当前已经完成的文件管理、打印机监控、实时看板、权限和任务状态能力。

## 2. 功能要求

### R1：基线和分支安全

- 不直接 `git pull`、整分支 `merge`、整分支 `rebase` 或使用远程版本覆盖本地文件。
- 集成必须在从 `2896a55` 创建的独立分支中完成。
- 每个子任务使用独立提交作为回滚点，不 force push，不覆盖远程同名功能分支。

### R2：视觉改动选择性移植

允许移植以下内容：

- TDesign 卡片、表格、分页、按钮、标签和工具栏样式。
- 页面标题、筛选区、操作区、空态和响应式布局。
- 打印机页面的表格悬停反馈、状态视觉层级和详情布局。
- 总览/全屏看板的统计卡片、趋势区域、头部和区域布局。
- 任务、历史、批量派发、个人中心和审计页面的纯展示调整。

视觉移植不得改变后端接口路径、字段、状态枚举、权限判断和数据来源。

### R3：文件管理能力不回退

必须保留并通过回归测试：

- 文件树和真实目录联动。
- PUBLIC/PRIVATE 可见性与资源 capability。
- 目录创建、移动、重命名、删除和文件批量移动。
- 单文件 1GB、最多 100 个文件、逐文件上传进度和部分失败结果。
- 文件详情、缩略图、下载和创建打印任务。

远程分支中的旧版文件库代码不得直接覆盖当前实现。

### R4：打印机监控和实时状态不回退

必须保留：

- 打印机业务状态与 `connectionStatus` 分离。
- 单台和批量监控开关，以及 ADMIN/OPERATOR 权限边界。
- 最近通信时间、错误摘要、连续失败次数和最后已知设备状态。
- REST 初始化后使用 WebSocket 增量更新。
- WebSocket 断线、陈旧、恢复中、快照、序号和事件去重处理。

### R5：任务状态和人工核对不回退

- 保留 `RECONCILING` 人工核对入口。
- 保留 `COMPLETED`、`FAILED`、`CANCELLED`、`QUEUED` 四种核对结果。
- 保留原因必填、重复提交保护、重新排队解除打印机绑定和操作后刷新。
- 保留批量派发 Preview 无副作用、Confirm 幂等、过期和部分失败恢复。

### R6：后端契约边界

- 本 Spec 不修改后端代码、数据库、OpenAPI 或接口路径。
- 文件树、目录权限、监控返回值和 reconcile 返回值存在文档漂移时，必须记录为契约待确认，不得在视觉任务中猜测修复。
- 动态 30×60 网格不在本 Spec 内实施；需要后端确认坐标范围和布局持久化后另立 `SYNC-002`。

## 3. 验收要求

- 现有 Node 测试、打印机监控测试、文件管理测试、WebSocket 测试和任务状态测试全部通过。
- `npm run lint`、`npm run build`、普通浏览器回归和 Electron/desktop-mock 回归通过。
- 主要页面在 800×560、1024×640、1200×760、1440×900 和 1920×855 下无页面级横向溢出。
- 业务操作的 Loading、Empty、Error、权限禁用、重复点击保护和错误提示保持有效。
- 集成提交只包含本 Spec 范围内文件，工作区无未提交的意外变更。
